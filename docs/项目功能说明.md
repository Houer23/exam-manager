# ExamManager 项目功能说明

> 适用对象：项目维护者与使用者。
> 本文档描述 `grade_analyzer` 的完整功能、数据模型、配置体系与运行机制；CLI 命令及参数详见《CLI命令参考.md》。

## 1. 项目概述与定位

本项目是一个**中学考试成绩处理与分析工具**（exam-manager），用于：

- 从不同格式的原始成绩表（Excel/CSV）解析出**规范表**；
- 完成数据清洗、排位、统计、班级汇总、个人成绩单、统计图与跨场合并分析；
- 以 Excel / CSV / PNG 形式输出结果，供教师、教务人员直接使用。

当前形态为 **纯 Python CLI + YAML 配置驱动**：所有操作通过 `python -m grade_analyzer.cli` 完成，所有配置通过 `config/` 下的 YAML 文件管理。

## 2. 总体架构与数据处理流水线

```
原始成绩表(data/input)
   │  check 校验（格式/名称/科目/满分）
   ▼
格式识别（weekly / joint / export，或插件注册格式）
   │  parse
   ▼
清洗与排位（考号/总分校验、班级归一化、学校过滤、班次/校次、单选多选区分）
   │
   ▼
规范表（data/parsed/<学期>/<考试名>/）
   ├─ score_summary.<fmt>     科目总分表
   └─ question_detail.<fmt>   小题明细表
   │  merge / run / results / charts
   ▼
分析产物（data/output/）
   ├─ merged/      合并长表/宽表
   ├─ statistics/  单场统计工作簿
   ├─ reports/     跨场汇总报告
   ├─ charts/      统计图 PNG
   ├─ quality/     check 报告 / 数据质量 / 名单核对
   └─ run-info/    每次 run 的配置快照与日志
另：results/       班级成绩汇总与个人成绩单
```

### 2.1 缓存复用规则

- 规范表已存在、且**原始文件 mtime 未变化**时，`parse` 直接复用缓存；
- 考试条目配置内容变化（`.config_sig` SHA-256 签名）或班级/学科配置变化（`.meta_sig` 签名）都会使缓存失效；
- `parse --reparse` 忽略缓存强制重新解析；
- 已删除考试的缓存目录保留，并写入 `.deleted` 删除标记。

### 2.2 运行记录（run-info）

每次 `run` 自动在 `data/output/run-info/<时间戳>/` 写入：

- `配置快照.yaml`：全局配置 + 参与考试的条目 + 班级/学科配置；
- `考试列表.csv`：本次参与考试的条目清单；
- `运行日志.txt`：各阶段事件（启动/解析/合并/统计/班级汇总/统计图/个人成绩单/报告/质量/完成）。

`data/output/run-info/latest/` 保留最近一次的固定副本。

## 3. 核心数据模型

### 3.1 科目总分表 `score_summary.<fmt>`

| 字段 | 说明 |
| --- | --- |
| `exam_name` | 规范考试名称（学期简写 + 科目 + 考试名） |
| `exam_type` | 考试类型（默认/学考/模考…） |
| `exam_date` | 考试日期（YYYY-MM-DD） |
| `student_id` | 12 位数字考号（合并键） |
| `name` | 姓名 |
| `class_name` / `class_raw` | 规范班级（高XDD班）/ 原始班级文本 |
| `grade` | 年级（高一/高二/高三） |
| `school` | 学校（单学校模型，默认学校过滤） |
| `subject` | 科目（规范名） |
| `total_score` / `objective_score` / `subjective_score` | 总分 / 客观分 / 主观分 |
| `full_score` / `objective_full_score` / `subjective_full_score` | 满分 |
| `total_ratio` / `objective_ratio` / `subjective_ratio` | 得分率（分/满分） |
| `班次` / `校次` | 竞争排名（同分同名次，可跳号） |
| `class_level` / `course` / `teacher` | 班级层次（A/B）/ 选科组合 / 任课教师（由班级/学科配置补齐） |
| `{题型}分` / `{题型}满分` | 动态题型分项列（如 单选分/多选分/听力分/作文分） |

### 3.2 小题明细表 `question_detail.<fmt>`

| 字段 | 说明 |
| --- | --- |
| `exam_name` | 规范考试名称 |
| `student_id` | 考号 |
| `question_id` | 规范题号：客观题 `N`；主观小题 `N-M`（单小题）；主观分组一列含多小题/圈码时保留括号形式，如 `17(1)(2)`、`19(1)(2)(3)①` |
| `question_type` | 题型（客观/主观/单选/多选/自定义题型） |
| `score` | 该题得分 |
| `full_score` | 该题满分（回填为该题最高得分） |

## 4. 配置体系与命名规范

所有配置为 YAML，由 `yaml.safe_load` 解析，**字段白名单强校验，未知键直接报错**。

### 4.1 全局配置 `config/config.yaml`

顶层键（`_GLOBAL_KEYS`）：`analysis`、`subjects`、`subject_aliases`、`subject_defaults`、`default_full_score`、`default_grade`、`current_semester`、`current_exam`、`default_school`、`input_dir`、`parsed_dir`、`parsed_format`、`exams_dir`、`classes_dir`、`subjects_dir`、`roster_dir`、`charts_dir`、`results_dir`、`results_config_dir`、`output_dir`、`report_excel_name`、`plugins`。

重点项：

| 键 | 说明 |
| --- | --- |
| `default_school` | 原始表无学校列时填充的默认学校；单学校模型只保留该校 |
| `current_semester` | run/merge/results 默认处理的学期 |
| `current_exam` | 场次序号列表（1-n 按日期升序；0=第一场；负数=倒数），留空处理全部 |
| `default_grade` | 班级归一化与成绩文件无年级时的默认年级 |
| `analysis.pass_ratio` / `excellent_ratio` | 及格线/优秀线（按得分率） |
| `analysis.absent_strategy` | 缺考处理：`exclude` / `include_zero` |
| `analysis.score_bands` | 分数段上界（降序，默认 `[0.9,0.8,0.7,0.6]`） |
| `plugins` | 插件白名单：缺省=自动发现全部启用插件；列表=白名单；`[]`=禁用全部 |

`subjects` 为科目词表（用于文件名识别）；`subject_aliases` 将别名映射到规范名（如 英语/俄语/日语 → 外语）；`subject_defaults` 为各科默认满分（`full_score`/`objective_full_score`/`subjective_full_score`）。

### 4.2 考试条目 `config/exams/<学期>/<考试名>.yaml`

一场考试一个 YAML。字段（`_EXAM_KEYS`）：`name`、`format`、`type`、`importance`、`folder`、`file`、`subject`、`semester`、`date`、`full_score`、`objective_full_score`、`subjective_full_score`、`objective_question_count`、`default_grade`、`sheet`、`filter_by_selection`、`short_name`、`question_display`、`show_big_questions`、`question_types`、`binary_split`。

| 字段 | 说明 |
| --- | --- |
| `subject` | 科目，**必填**（check 校验） |
| `semester` | 学期全称；省略时取子文件夹名，显式声明优先 |
| `date` | YYYY-MM-DD；留空取程序运行当日 |
| `folder` / `file` | 原始成绩文件；`file` 必填，`folder` 留空取全局 `input_dir` |
| `name` | 考试名称；留空从文件名 `--...】` 提取，提取失败 check 不通过 |
| `format` | `weekly` / `joint` / `export`（或插件格式）；留空自动识别 |
| `type` | 考试类型（联合分析筛选用），缺省 `默认` |
| `importance` | 平时/联考；留空由格式推导（joint→联考，weekly→平时） |
| `question_display` | `split`=小题分列 / `merged`=按大题合并 |
| `show_big_questions` | 是否额外显示主观大题汇总列 |
| `objective_question_count` | 客观题数；留空按题号格式自动判定 |
| `question_types` | 题型配置（见 5.3） |
| `binary_split` | 二分配置（默认 true），见 5.3 |
| `filter_by_selection` | 名单核对是否按七选三过滤，默认 true |

**规范考试名称** = 学期简写 + 科目 + 考试名（已含学期/科目或其别名时不重复添加）。

### 4.3 班级配置 `config/classes/<学期>.yaml`

班级名（默认学校）→ `{level: A|B, course: 选科组合}`。`level` 只能 A/B，`course` 为自由文本。

### 4.4 学科配置 `config/subjects/<学期>_<科目>.yaml`

- `subject`：科目名；
- `teacher_count`：教师数量，必须与 `teacher_names` 数量一致；
- `teacher_names`：代号（**A 起连续大写字母**）→ 教师名；
- `class_teachers`：班级 → 代号；使用时转换为教师名。

未配置教师的班级不生成班级汇总（check 会 WARN）。

### 4.5 图表配置 `config/charts/config.yaml`

统计图参数：`enabled`、`format`（png/svg/pdf）、`dpi`、`figure_width`、`row_height`、`min_figure_height`、`group_by`（`层次`/`教师` 组合）、`sort_metric`（median/mean/q1/q3）、`show_violin`、`show_lines`、`axis`（范围模式/刻度/坐标轴标签/横轴扩展系数）、`font`、`colors`（调色板与指标颜色/点形）、`violin`（半提琴参数）、`annotations`（ave/std 与 M/Q1/Q3 标注）、`separator`（组间分隔线）。

### 4.6 成绩单配置 `config/results/config.yaml`

- `personal`：范围（`scope.mode` = `teacher`/`all`/`custom`，`teachers`/`classes`）、排序、单/多 sheet、大题列前后缀、总分加粗、布局（空行/行高/列宽/字体/对齐/边框）、页眉页脚、打印（纸张/方向/边距/每页行数）；
- `class_summary`：按教师分文件、每班一 sheet、全部班级汇总、页眉页脚、字体、列宽、对齐、边框（可选去单选/多选之间与同大题小题之间的竖线）、数据条、平均行（全班/前半/后半）。

### 4.7 YAML 写法注意事项

- 纯中文/英文单词可不带引号；**日期与含特殊字符的值必须用双引号**；
- 数值（`full_score: 100`）与布尔（`filter_by_selection: true`）不要带引号，否则会被解析成字符串；
- 空字符串与 null 统一视为"未设置"；
- 修改配置后建议运行 `check` 确认可正常加载。

## 5. 功能详述

### 5.1 格式解析

| 格式 | 特征 | 说明 |
| --- | --- | --- |
| `weekly`（格式 A，周测/平时） | 表头含 `自定义考号/总分/班级` | 总分/客观分/主观分为权威列；考试名从文件名提取；小题列在 `解答题` 之后 |
| `joint`（格式 B，联考） | 表头含 `考号/学校/班级` 且其后存在字母答案列 | 无总分列，全部由得分列求和；纯数字题号=客观题，`N-M`=主观题 |
| `export`（平台导出） | 第 0 行表头含 `考生号/任课教师/选择题_1` | 班级数字码 `25XX` 映射为 `高一XX班`；选择题选择项列不进小题明细 |

格式自动识别按注册顺序调用各适配器 `detect()`；`check` 会打印格式识别预览与班级样例。

### 5.2 清洗与校验

- **考号校验**（硬失败）：缺失、非 12 位数字、场次内重复 → 报错终止；
- **总分校验**（硬失败）：`0 <= 总分 <= 满分`；
- **班级归一化**：`高一年级4班/高一(10)/3` → `高一04班`/`高一10班`/`高一03班`；无法归一化进入质量清单；
- **学校过滤**：单学校模型，只保留默认学校（无学校列时填充默认学校）；
- **竞争排名**：班次按（学校,班级）分组、校次按学校分组，同分同名次、可跳号；缺考排位为空；
- **单选/多选自动区分**：客观题配置未含单选/多选时，按各题实际最高得分区分（得分大的为多选）；全部相同则无多选；
- **质量清单**：客观/主观超满分、客观+主观≠总分、班级无法归一化等软问题进入 `数据质量.xlsx` 与报告"数据质量" sheet。

### 5.3 题型配置 `question_types`

值为**数量式**（纯数字，按顺序从 1 起连续分配，只能出现在前面若干行）或**题号列表式**（逗号/短横线，如 `1,2,3-5`、`"5,"`=题号 5）：

```yaml
question_types:
  听力: 5            # 1-5 题
  阅读: 10           # 6-15 题
  客观题: 16-30      # 列表式
  单选: 16-22        # 子题型（范围完全含于 客观题）
  多选: 23-30
  主观题: 31-35
```

规则：

- 范围**完全包含**时为子题型，部分重叠报错；
- 每题题型取包含该题号的最深子题型；
- `binary_split=true` 且顶层题型数 ≤2 时：客观/主观范围由 `objective_question_count` 确定，配置题型作为子题型；`false` 时完全按配置划分；
- 分项列按题型动态生成（如 `听力分`、`作文分`、`单选分`/`多选分`），成绩单按存在的分项列显示；
- `--question-types` 交互文本格式：`题型名,数量或题号列表;...`，全半角标点兼容。

### 5.4 `check` 校验

逐场检查：文件存在、格式识别、名称提取、科目、班级样例、满分来源、元数据覆盖（有成绩但未配置教师的班级 / 学科配置中但数据未出现的班级 / 未配置 level/course 的班级）。

状态：PASS / WARN / FAIL。**首次检查后写入已检查标记**（`data/output/quality/checked/<考试名>.yaml`，含原始文件 mtime 与 FAIL 数）；再次检查且原始文件未变化时跳过该场详细打印，只显示一行概要。`--force` 强制重查。

报告落盘：`quality/check_<考试名>.csv` 与 `quality/check_汇总.csv`。

### 5.5 单场统计工作簿

`statistics/<学期>/<考试名>.xlsx`，5 个 sheet：

1. **科目统计**：考生数/平均分/最高分/最低分/标准差/平均得分率/及格率/优秀率；
2. **分数段分布**：得分率口径，`90+ / 80-89 / ...`，60 分以下每 10 分细分至底段占比 <0.1，含正向/逆向累计占比；
3. **个人排名**：总分降序，缺考排最后，含班次/校次；
4. **班级对比**：按（层次,班级）分组，组内按平均得分率排名；
5. **教师对比**：按教师分组，同口径。

内嵌图表：分数段柱状、班级对比条形、教师对比条形。

### 5.6 班级成绩汇总

按配置生成：

- `group_by_teacher=true`：每个教师一个文件 `data/output/results/<学期>/<考试>/<考试>_<教师>_班级成绩汇总.xlsx`，每班一个 sheet；
- `all_classes_summary=true`：额外生成 `<考试>_全部班级_班级成绩汇总.xlsx`。

每个班级 sheet：学生明细（序号/姓名/总分/客观分/主观分/题型分列/小题分列或大题合并/班次/校次）、末尾平均行（全班/前半/后半）、页眉（班级/考试名/日期）、页脚（班级与年级均分/中位数/标准差，含 A/B 层次对照）、数据条与边框样式。

### 5.7 个人成绩单

- 范围：`mode=all`（全部班级）、`mode=teacher`（按教师分文件，标签=教师名）、`mode=custom`（自定义班级，标签自动判定为 全部班级/教师名/自定义）；
- 每个学生一个"成绩条"（表头+数据行+空行），自动分页保证表头与数据同页；
- `question_display=split` 小题分列 / `merged` 按大题合并（`值|值|值`）；
- 多场（≥2）时默认合并为一份：每生一个表头、每场一行，主观题列为各大题得分竖线合并字符串；`--no-merge-strips` 可关闭合并；
- 文件名：`<yyyymmdd>_<考试>_<标签>_个人成绩单.xlsx`（多场合并：`<日期范围>_<标签>_个人成绩单.xlsx`）。

### 5.8 统计图（charts）

- **单场组合图**：按 `group_by`（层次/教师）各生成一张半提琴图 + Q1/中位数/平均分/Q3 指标折线组合图；文件 `按<分组>_<日期8位>_<考试名>.png`，标题左侧显示考试日期；
- **班级×考试图**：`--class 10,11` / `10-12` / `14-12`（反向区间），多班级一张图或 `--per-class` 每班一张；文件 `按班级_<日期范围>_<班级标签>.png`；
- 样式全部由 `config/charts/config.yaml` 控制（含 `xlim_factor` 为标注预留空间、`violin.width` 半提琴宽度）。

### 5.9 跨场合并（merge）

合并键：12 位考号；学生集合并集；未参加某场=缺失（区别于 0 分）；班级取最近一场；跨场比较一律用得分率。

- **长表**：各场 `score_summary` 拼接（小题明细不拼接）；
- **宽表**：考号 × 场次（每场 `总分` + `得分率` 两列，按日期升序），附班级/年级/学校（最近一场）、平均得分率、参考场次；
- 筛选：`--semester`、`--types`、`--subject`、`--baseline-exams`（额外加入历史场次作比较基准）；
- 单场（<2）不落盘合并文件；多场文件名标注日期范围：`merged_long_20260325-20260420.csv`。

### 5.10 跨场汇总报告

`reports/<学期>/成绩分析汇总_<日期范围>.xlsx`，9 个 sheet：科目统计、分数段分布、个人排名（各场拼接）、班级对比、教师对比、**多场趋势**、**学生进退步**（得分率变化与校次变化，状态=进步/退步/持平）、数据质量、配置说明。内嵌多场趋势折线图。

### 5.11 名单核对（roster）

名单文件：`data/roster/<学期>.xlsx`（单 sheet 长表：姓名/考号/性别/七选三/班级）。

- `normalize`：清洗（12 位考号/重复/班级缺失/班级无法规范化）并生成 `<学期>_normalized.xlsx`（名单+异常两 sheet），原始文件更新后自动重新生成；
- `check`：名单 vs 有成绩学生 → 缺考/未参加、名单外、姓名不符；可按七选三过滤（`filter_by_selection`）；差异清单落盘 `quality/名单核对_<考试名>.csv`。

### 5.12 插件系统

程序启动时扫描 `plugins/` 目录加载插件（`plugin.yaml` 清单 + `plugin.py` 入口 `register(ctx)`）。可注册：

- **格式适配器**（`ctx.register_adapter`）：参与自动识别与解析；
- **生命周期钩子**（`ctx.register_hook`）：`on_run_start` / `on_exam_parsed` / `on_exam_finished` / `on_run_finished`；
- **批处理任务**（`ctx.register_task`）：通过 `task` 子命令独立调用。

内置插件 `objective_analyze`：读取"客观题得分明细"文件夹（各班 `N班.xls` + `全部班级.xls`），生成客观题得分汇总工作簿与得分率距平文件；支持按教师/层次分组、基线（全部班级或分组名）、低得分率阈值等，参数见 `plugins/objective_analyze/config.yaml`。

### 5.13 模板工具

- `template_tools.py generate --type all`：重新生成模板（相关配置文件缺失时一并生成）；
- `template_tools.py scan --mode existence`：只补缺失，不覆盖；
- `template_tools.py scan --mode diff`：模板与内置默认值不同则重新生成；
- `sync_templates.py`：把 `config/charts/config.yaml` 与 `config/results/config.yaml` 同步到对应 `_template.yaml`。

## 6. 标准使用流程与命令依赖

```
模板初始化（新环境）→ exam add → check → parse → {run | results | charts | merge}
```

- `results` / `charts` / `merge` / `roster check` **硬依赖 parse**：规范表未就绪会提示"请先运行 parse"并正常结束；
- 一句话流程：**放数据 → exam add → check → parse → exam list --results-ready → results / charts**；
- 原始文件更新、考试条目配置（题型/客观题数）或班级/学科配置（任课教师/层次）变化都会使规范表缓存失效，需重新 `parse`（或 `parse --reparse`）。

## 8. 数据安全与注意事项

- `data/input/`、`data/parsed/`、`data/roster/`、`data/output/` 均被 `.gitignore` 忽略：原始成绩、名单（含考号/选课）与生成结果不入库；
- `config/` 中可能含真实教师姓名等信息，仓库应保持私有，开源前需脱敏；
- 实际配置（`config.yaml`、图表/成绩单配置、考试条目、班级/学科配置）不入库，仅模板入库；新环境先运行 `template_tools.py scan --mode existence`；
- 所有文本文件统一 CRLF 行尾（`.gitattributes` 强制）；
- 插件为本地 Python 代码，以完全权限执行，只应加载可信来源的插件。
